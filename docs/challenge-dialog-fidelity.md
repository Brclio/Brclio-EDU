# 课程挑战窗口与入口（2026-11-02）

原站公开组件 `Ym` / `C0t` 与实际 `https://edu.py2fun.com/learn#/course/023/catalog` 的第一个 C++ 挑战同时核实。匿名点击该已开放挑战后，地址仍为课程目录，显示全屏挑战窗口；没有登录或绕过锁定课节。首次欢迎遮罩通过原版“立即学习”操作关闭后再回目录。

本地新增 `ChallengeDialog.tsx`，保持以下原结构：60px顶栏、左右各50%、48px内栏、左侧题面/测试结果/提交记录、右侧原版Monaco、480px答案抽屉、400px退出/重置确认、180px绿色完成区。原题说明、输入/限制/输出、最多前三个公开样例、原提示与原答案均取本地课程JSON；源码、资源及运行器不回连原站。

入口分别按原公开实现恢复：

| 入口 | 原实现 | 本地行为 |
| --- | --- | --- |
| 目录 `page.coaches` | `lse` → `Ym` | 点击原位置的挑战卡，留在目录打开全屏窗口，关闭返回原目录位置 |
| 目录 `category.coaches` | `/coach/:id` → `rNt` → `Ym hideAnswer=true` | 现有本地挑战路由直接显示窗口，隐藏答案入口，退出回课程目录 |

挑战实际执行使用既有同源 Python/JavaScript/SQL Worker 或隔离服务器运行器。不会因为 `done`、普通stdout或空测试数组判定通过；必须非空公开测试全部成功且本次运行无错误。缺少公开测试时明确给出自查输出，不伪造原站隐藏判题。

`tests/challenge-dialog-audit.mjs` 五组真实浏览器流程通过：

- 目录弹窗尺寸、地址不变、查看只读答案、重置确认/取消、退出确认/继续。

## 当前判题状态失效回归

最终复核修正一处状态问题：成功执行后，如果继续编辑主代码/附加文件或确认重置，旧的成功结果不能属于新代码。现会清除当前结果、错误/状态、输出与产物，并将结果页退回题面；成功绿色区消失，关闭重新出现退出确认。已获得的历史完成记录与提交历史保留。

`tests/challenge-dialog-audit.mjs` 现为七组通过，新增两组真实 Python 流程分别覆盖“通过→粘贴错误代码”与“通过→确认重置”，均断言成功区/结果页消失、退出确认恢复、历史完成仍为true、提交记录不丢失。该局部修复之后重跑挑战专项与TypeScript/Vite构建，没有将此前App全量报告说成针对本次局部改动重新跑过。

原站最多三个公开样例的准确依据：本机源文件 `data/source/index-c6fcd669.js` 第467行、函数 `z1t`，开头为 `const t=(e.testcases||[]).filter(r=>r.sample).slice(0,3)`；紧随的题面组件 `q1t` 调用 `z1t(e)`。第四个公开sample因此保留在JSON和真实判题中，但不显示在原站题面，本地按相同显示规则处理。
